# devlens-rules

SDK and framework detection rules for DevLens, an on-device APK/AAB inspector for Android.

The app ships a copy of these rules and checks this repo once a day, on an unmetered network only. It reads:

```
https://raw.githubusercontent.com/nguynduyanh169/devlens-rules/main/v1/rules_latest.json
https://raw.githubusercontent.com/nguynduyanh169/devlens-rules/main/v1/<file from the manifest>
```

## Layout

| Path | What it is |
|---|---|
| `v1/rules_latest.json` | Manifest: `schemaVersion`, `version`, `publishedAt`, `file`, `size`, `sha256` of the current rules db |
| `v1/rules-<version>.db` | SQLite rules db, schema v1. The file name carries the version and never changes once published |

`v1/` matches `schemaVersion` 1. A schema change is published under `v2/`; apps that only read v1 keep reading `v1/`.

The app uses a download only if its size and SHA-256 match the manifest, its schema passes the reader's checks, and its `version` is higher than the bundled one.

## Publishing

Every file here is generated by `rules/build.sh` in the DevLens repo, from `rules/schema.sql` and `rules/rules.sql`. Don't edit them by hand.

1. In DevLens: edit `rules/rules.sql`, bump `version` in its `meta` rows, run `bash rules/build.sh`.
2. Copy `rules/dist/v1/rules-<version>.db` into `v1/`, commit and push.
3. Then copy `rules/dist/v1/rules_latest.json` into `v1/`, commit and push.

Push the db before the manifest, so a manifest never points at a file that isn't there yet. Versions only go up: a bad publish is replaced by a higher version, never by rewriting an old one.
